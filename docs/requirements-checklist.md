# Requirements checklist

This checklist maps every requirement in [requirements.md](requirements.md) (R0.1 to R26.1) to its
status and its evidence. It is the requirements-to-tests checklist that R3.5 asks for. The
feature-by-feature view is in [feature-matrix.md](feature-matrix.md).

**Scope of the claims.**

* Nothing was published, pushed, migrated for real, or enabled in the real Locus checkout.
* Host evidence comes from the patches in [`handoff/locus/`](../handoff/locus/README.md), and those
  patches were tested only in disposable copies of Locus `b332e455`.
* No production-readiness claim is made, and no measured quality gain beyond
  [evaluation.md](evaluation.md) is claimed.

## How to read this checklist

| Status | Meaning |
|---|---|
| **met** | The package or this repository satisfies the requirement. The evidence is cited. |
| **partially met** | Part of the requirement is satisfied. The notes name the part that is missing. |
| **not met** | The requirement is not satisfied. |
| **not executed** | The work was prepared, but the step the requirement describes was not run. Examples: a real host, a release, a benchmark arm. |
| **host-side** | Locus has to satisfy the requirement. The evidence is the handoff patches and their host tests, which ran only in a disposable Locus copy. The notes say how much of the requirement the patches cover. |

* **Package tests.** `tests/test_x.py::test_y` is a package test. Every cited name was checked
  against `pytest --collect-only` output on 2026-10-04, and checked again after review round 4.
  Within one cell, `::test_z` after a full path means the same file, and `::test_x_*` means every
  test of that file whose name starts with `test_x_`.
* **Host tests.** `agent/tests/test_memory_adapter.py::test_y` is a host test. It is defined in
  `handoff/locus/0002-stage2-memory-adapter.patch`, and it ran only in a disposable copy (handoff
  README §7).
* **Code.** Code is cited as `module.Class.method`, relative to `src/locus_memory/`.
* **"No test."** When a row says "no test" or "by reading", nothing in the suite asserts that
  behaviour. The claim rests on reading the code.
