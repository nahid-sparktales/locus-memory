# Feature matrix

This document gives the status of each feature area of `locus-memory` 0.1.0 and of its Locus
integration as of 2026-10-04. It also lists the evidence for each status. The requirement-by-requirement view is in
[requirements-checklist.md](requirements-checklist.md).

**Scope of the claims.**

* Nothing was published, pushed, migrated for real, or enabled in the real Locus checkout.
* The host integration exists only as patch files in [`handoff/locus/`](../handoff/locus/README.md),
  tested in disposable copies of Locus `b332e455`.
* The evaluation is synthetic ([evaluation.md](evaluation.md)). Two of its pre-registered rollout
  criteria are not met.
* No production-readiness claim is made, and no measured quality gain beyond
  [evaluation.md](evaluation.md) is claimed.

Related documents: [architecture.md](architecture.md), [storage-and-encryption.md](storage-and-encryption.md),
[security-and-privacy.md](security-and-privacy.md), [integration-locus.md](integration-locus.md),
[integration-workflows.md](integration-workflows.md), [migrations-and-rollback.md](migrations-and-rollback.md),
[repository-interchange.md](repository-interchange.md) and [PROGRESS.md](PROGRESS.md).

## How to read this document

| Status | Meaning here |
|---|---|
| **implemented** | The feature is in the package, and package tests exercise it. The package suite passes on CPython 3.10.22 and 3.14.6. |
| **implemented (by reading)** | The feature or artefact exists in this repository (code, licence files, documents, recorded result files), but no package test asserts it. The claim rests on reading those files. |
| **implemented (script)** | Checked by a hand-run script outside the pytest suite (`scripts/verify_wheel.sh`). |
| **implemented (host patch; disposable-copy tests only)** | The change exists only as a patch in [`handoff/locus/`](../handoff/locus/README.md). It was applied and tested only in disposable copies of Locus, never in the real checkout. The package suite does not run these tests. |
| **experimental** | Implemented and tested, but heuristic, or measured with a rollout criterion still open. Do not make it a default without the condition given in the notes. A suffix such as "(untested)" or "(host patch; disposable-copy tests only)" narrows the evidence the same way as for implemented rows. |
| **contract-only** | The interface, validation and governance exist, but only deterministic fakes or test stand-ins implement it in this repository. No production implementation ships. |
| **deferred** | Not implemented. Left for a later stage or for an open decision. |
| **blocked** | Cannot proceed in this repository because an upstream artefact does not exist. |
| **not executed** | Implemented or prepared, but the step that would run it against a real system was not run: a real Locus checkout, real data, a release, or a host runner. |

## 20. Gaps found while compiling this matrix

These gaps come from reading the code and the patches; the residual part of gap 3 was also
reproduced with a scratch probe. When this matrix was written, none of them was recorded in the
handoff README.

1. **Stage-2 archive and session deletion.** `MemoryAdapter` in patch 0002 forwards no Locus session
   deletion to the engine. With `LOCUS_MEMORY_ARCHIVE=1`, a deleted session's archived copy stays in
   `APP_DIR/memory-engine/` until that directory is deleted. No test covers this.
2. **Stage-2 archive sequence numbers.**
   * `MemoryAdapter._next_sequence` uses a microsecond clock. Because of that,
     `history.archive.HistoryArchive._note_arrival` records `not_received` gaps before and between
     archived messages, and the per-producer cursor never advances.
   * Messages committed without an event id or `_item_id` get a random event id, so they are not
     de-duplicated on replay.
   * No test covers this.
3. **Imported repository records approved after their cited file changed stay current until
   the repository changes again.** The gap originally listed here was fixed in review round 3
   (R3-EG-1): approved imported summaries and observations now go stale when a cited file
   changes or is deleted (§8). A residual gap remains:
   * `repository.service.RepositoryService._settle_derived` re-checks imported records only in
     a snapshot with a new identity. A repeated snapshot of an unchanged repository (same HEAD,
     dirty state, root and exclusions) is reused and settles nothing.
   * So a candidate that is approved after the snapshot that saw its cited file change stays
     approved, and is served, until a later snapshot sees some change in the repository.
   * A scratch probe on 2026-10-04 reproduced this. The `_settle_derived` docstring says that
     a candidate approved later is staled by the next snapshot, which holds only when that
     snapshot is not reused. No test covers it.
4. **No test forces FTS5 off for the history archive.** The substring matcher itself is exercised
   by the CJK fallback (`tests/test_history.py::test_fts_queries_identifiers_and_unicode`). Only
   the no-FTS5 projection setup (`history.archive._Projection` with `use_fts=False`) is untested
   (§5).
5. **Unused code.** `models.StorageRole` is defined but not used, and `locus_memory.testing` is an
   empty subpackage.
6. **Some limitation texts are not asserted.** No test checks the text of
   `forgetting._FORGET_LIMITATIONS`, `forgetting._APPLIED_ELSEWHERE` or
   `models.EngineStatus.limitations`. These are asserted:
   * the admin rotation receipt limitations, in `tests/test_review_group2.py` (§2);
   * the conditional forget-receipt limitations `forgetting._PURGE_PENDING`, `_MIGRATION_RESIDUE`,
     `_LEGACY_AUTHORITY`, `_ROLLBACK_PENDING` and `_CUTOVER_PENDING`, in
     `tests/test_review_round2_batch2.py`, `tests/test_review_round2_batch3.py`,
     `tests/test_review_round3_batch1.py`, `tests/test_review_round3_batch2.py` and
     `tests/test_review_round4_batch2.py` (§13);
   * `core.CONFLICT_SCAN_LIMITATION`, in `tests/test_review_round2_batch4.py` (§4).
